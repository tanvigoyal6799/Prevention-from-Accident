# Road Safety Alert (v0.2)

Dashboard prototype for cooperative road safety. A driver registers, allows location, searches a destination,
and starts a trip. During the trip the app shows nearby app users within 150 m (Green / Yellow / Red / Grey)
and an **overtaking advisor** (Safe / Wait / No) based on the route ahead and known oncoming vehicles.

> **Prototype only. Not a validated safety system.** Green means no *known app user* is in the way,
> not that the road is clear. Do not use the screen while driving. Follow road markings and the law.

## Flow
Register / Log in -> Allow location (consent) -> Search destination -> Route on map -> Start trip -> Dashboard

## How the overtaking advisor decides
1. Find the nearest slower vehicle ahead on my route (within 80 m).
2. Estimate time and distance needed to pass it (simplified model).
3. **Red:** a known oncoming vehicle would be reached before the pass is finished.
4. **Yellow:** a faster vehicle is close behind, GPS is weak, or a bend / limited view lies within the distance needed.
5. **Green:** none of the above. **Grey:** nothing to overtake, not moving, or off route.

The model is simplified. Calibrate it against IRC SP:23 / AASHTO passing sight distance before any real use.
It cannot see vehicles without the app, road markings (no-overtaking zones), crests or junctions.

## Run locally
```bash
pip install -r requirements.txt
SECRET_KEY=change-me uvicorn server:app --port 8000     # Windows: set SECRET_KEY=change-me first
# open http://localhost:8000, register, allow location, choose a destination, tick "Simulation mode" to demo
```
Tests: `pip install -r requirements-dev.txt && pytest`

## Where the APIs and keys go
| Need | Used now | Where the key goes |
|---|---|---|
| Map tiles | OpenStreetMap (free, no key) | Nothing. For heavy traffic use a tile provider (MapTiler, Mapbox) and put its key in the client config |
| Search (geocoding) | Nominatim via `/api/geocode` | No key. Policy: 1 request/s, identify your app in `UA` in `server.py`. For production use Photon, LocationIQ or Google Places |
| Routing | OSRM demo server via `/api/route` | Optional `ORS_API_KEY` (openrouteservice.org, free tier) as a **server environment variable** |
| Login tokens | `SECRET_KEY` | Server environment variable. Never commit it |

All keys stay on the server (Render: Environment tab). The browser never sees them.

## Deploy (Render)
1. Push to GitHub. 2. Render: New, Blueprint, select repo. 3. In Environment set `ORS_API_KEY` (optional).
`SECRET_KEY` is generated by `render.yaml`.
**Important:** the free tier has no permanent disk, so the SQLite user database is wiped on each redeploy.
For real users use a managed Postgres (Render, Supabase, Neon) and switch the `run()` helper in `server.py` to it.

## Privacy
Passwords are hashed with scrypt. Live positions exist only in server memory for a few seconds, use a random
per-connection ID, and are never linked to the account. Add a privacy policy and terms before a public launch.

## Known limitations
Only app users are visible. GPS error is 3 to 10 m (worse in hills). No lane-level detection, no crest/gradient data,
no offline mode, single server instance, no password reset or email verification yet.

## Roadmap
